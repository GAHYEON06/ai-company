# 포근 컴퍼니 · 나만의 AI 사무실

GitHub Pages의 첫 화면은 `index.html`의 귀여운 사무실 UI입니다. 모모·루루·콩이·피치·토비·체리·가디를 눌러 역할을 확인하고, 담당자를 선택해 업무 브리핑을 보관할 수 있습니다. 모바일 화면도 지원합니다.

화면에서 등록한 업무는 해당 브라우저에 저장됩니다. PC 연결 프로그램을 켜고 API 키를 설정하면 웹에서 실제 에이전트에게 전송하고 진행 상태·답변·확인 요청을 받을 수 있습니다. GitHub Issue 생성은 자동으로 수행하지 않습니다.

## 웹에서 AI 연결하기

1. 프로젝트 폴더에서 `npm run office`를 실행합니다. Windows에서는 `Start-Office.cmd`를 직접 열어도 됩니다.
2. `http://127.0.0.1:4173/connect`에서 OpenAI API 키를 직접 입력합니다. **키를 채팅이나 GitHub에 보내지 마세요.**
3. **사용 가능한 모델 확인**을 누른 뒤 사용할 모델을 선택하고 **암호화해 저장하고 AI 시작**을 누릅니다. 모델은 자동으로 다른 것으로 바뀌지 않습니다.
4. PC 사무실은 `http://127.0.0.1:4173`에서 바로 사용할 수 있습니다. GitHub Pages 사무실은 상단의 연결 표시를 누르고 **이 PC 연결 · API 키 설정**을 누릅니다.
5. PC 설정 창에서 **이 사무실과 PC 연결하기**를 눌러 페어링합니다. 브라우저가 로컬 네트워크 연결 권한을 요구하면 `127.0.0.1`의 내 실행 프로그램으로 연결하는 요청인지 확인합니다.
6. 연결 표시가 **AI 연결됨**으로 바뀌면 업무를 전송합니다. 업무 보드에서 결과·실제 도구 호출 진행·중지·AI의 확인 질문을 확인할 수 있습니다.

연결 프로그램과 PC를 켜둔 동안 사용할 수 있습니다. 휴대폰 등 다른 기기의 `127.0.0.1`은 그 기기를 가리키므로 이 PC로 자동 연결되지 않습니다. 모델 호출은 선택한 OpenAI API 계정의 사용량으로 처리됩니다.

### 키와 업무 보호

- API 키는 Windows DPAPI의 현재 사용자 범위로 암호화하여 `.eve/office/key.dpapi`에 보관합니다. 이 경로는 Git에서 제외됩니다.
- GitHub Pages는 API 키를 받지 않습니다. 브라우저 탭에는 페어링 토큰만 세션 범위로 보관합니다. 연결 프로그램을 재시작하면 다시 페어링해야 합니다.
- 서버는 `127.0.0.1`에만 바인딩하며, 허용된 사무실 출처·Host·페어링 토큰을 확인합니다. 설정 API는 PC 설정 페이지에서만 사용할 수 있습니다.
- 요청마다 동일한 업무 ID를 사용하여 응답 유실 후 다시 누르더라도 같은 업무를 중복 생성하지 않습니다. 자동 재전송은 하지 않습니다.
- 한 번에 업무 하나를 처리하며, 작업 중지와 15분 실행 제한이 있습니다. 서버 재시작 시 진행 업무는 중단으로 표시하며 자동 재실행하지 않습니다.
- 실행 기록과 결과는 `.eve/office/jobs.json`에 보관합니다. AI 답변은 검증된 실행 결과와 구분해 확인해야 합니다.

PC에서 화면만 미리 보려면 다음 명령을 실행하고 `http://127.0.0.1:4173`을 엽니다.

```powershell
npm run ui
```

미리보기 서버는 로컬 주소에서 UI 파일만 제공합니다. GitHub Pages는 저장소 루트의 `index.html`을 첫 화면으로 표시합니다.

대표가 목표를 지시하면 총괄과 조사·기획·설계·개발·QA·보안 에이전트가 협업하는 초기 프로젝트입니다.

## 운영 구성
- 소스와 작업 이력: GitHub 저장소
- 자동 검사: GitHub Actions의 타입 검사와 알려진 의존성 취약점 검사
- 의존성 업데이트 제안: Dependabot
- 에이전트 실행: 내 PC의 eve 터미널
- 모델 연결: PC에 저장한 OpenAI API 키로 직접 연결. Vercel AI Gateway를 사용하지 않습니다.

Vercel 계정이나 배포가 필요하지 않습니다. eve와 그 의존성에는 Vercel이 제작한 라이브러리가 포함되지만 Vercel 호스팅과는 별개입니다. GitHub 저장소 자체가 AI 모델을 제공하거나 에이전트 서버를 상시 실행하지는 않습니다.

## 시작
Node.js 26을 사용합니다. 프로젝트 폴더에서 실행합니다.

```powershell
npm ci
npm run dev
```

실행 화면의 `/login`에서 모델 연결을 설정합니다. 기본 설정은 OpenAI 직접 연결이며 기존 모델 ID를 유지했습니다. 계정에서 사용할 수 있는 모델인지 확인해야 합니다. ChatGPT 구독 연결과 API 연결의 지원 범위는 실행 화면에서 확인하세요. 비밀키나 인증 코드를 채팅, 소스, GitHub에 올리지 마세요.

첫 지시:
> 개인 일정 관리 웹앱을 만들어줘. MVP 기획부터 설계, 개발, QA와 보안 검토까지 진행하고 결과 파일과 테스트 근거를 보고해줘.

## GitHub 업무 흐름
1. Issue에 목표와 완료 조건을 적습니다.
2. 에이전트가 PC에서 작업하고 코드와 패치를 반환합니다.
3. 작업 브랜치를 올리고 PR로 검토합니다.
4. GitHub Actions에서 타입 검사와 의존성 취약점 검사를 실행합니다.
5. QA·보안 검토 후 반영합니다.

현재 GitHub Issue의 자동 수신, PR 자동 생성, 이슈 댓글 응답은 연결하지 않았습니다. 웹 업무 전송은 PC 연결 프로그램을 통해 이루어집니다. Actions는 AI를 호출하지 않으므로 AI 비밀키가 필요하지 않습니다. 의존성 감사는 높은 위험 이상의 알려진 취약점이 있으면 실패합니다. 인증·권한·XSS 등의 검토는 보안 에이전트의 별도 업무이며 npm 감사가 이를 대체하지 않습니다.

## 에이전트와 보안
총괄은 별도 컨텍스트와 파일시스템을 갖는 6개 전문 에이전트에게 필요한 자료를 전달하고 결과를 통합합니다. 최종 변경본을 QA와 보안 담당에게 재검토하도록 지침을 설정했습니다. 보안 담당은 위험도, 근거, 수정안, 재검사 결과를 보고하며 미검증 항목을 안전하다고 표시하지 않습니다. 심각/높음 미해결 문제에 대한 출시 보류는 업무 지침이며 강제 배포 차단 기능은 아닙니다.

## 확인 명령과 제한
```powershell
npm run typecheck
npm run test:bridge
npm run audit
npm run build
```

- 모델을 사용한 전체 협업, 실제 앱 제작, 보안 스캐너 실행은 아직 검증하지 않았습니다.
- 실제 앱 빌드와 테스트를 실행하려면 Docker 등의 실행 환경이 필요합니다. 이전 빌드는 Docker가 없어 샌드박스 경고를 냈습니다.
- 웹 사무실과 PC의 AI 실행 서버 연결을 포함합니다. Docker가 없는 경우 네이티브 앱 빌드나 브라우저 테스트는 수행할 수 없으므로 미검증으로 보고합니다.
- HTTP 채널은 로컬 개발 인증만 사용합니다. 외부에 공개하려면 사용자 인증을 별도로 설정해야 합니다.
- GitHub Actions의 통과는 타입 검사와 알려진 의존성 취약점 검사에 한정됩니다.
